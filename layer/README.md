# VK_LAYER_XESS_xmx

A Vulkan layer that runs XeSS' XMX kernels on an **unpatched** Mesa ANV. It does what `patches/0001` does inside
the driver, but from outside, so the distribution's own `vulkan-intel` package can be used. It works with the
same shim (`igdext64.dll`), both the hash placeholders and the id placeholders of older shims.

Status: experimental. It is not part of the release archive or `install.sh` yet.

## How it works

* The layer recognises the shim's placeholder compute shaders in the SPIR-V that vkd3d-proton passes to
  `vkCreateComputePipelines` (`src/placeholder.c`).
* For a placeholder it compiles the kernel with `tools/cm-compile.sh` (`CM_NO_LOAD_PAYLOAD=1`: the kernel expects
  its payload in registers instead of loading it). Kernels are cached as `~/.cache/xess-xmx/kernels/*.cml`.
* It puts a short prologue in front of the kernel that loads the payload. The prologue is built from a table of
  instruction encodings (`src/prologue_table.inc`, generated by `tools/gen_prologue_table.py`), so the layer needs no
  assembler at run time.
* It wraps the result into the driver's own serialized shader form, taken from a template shader the driver
  compiled (`src/anvbin.c`, `src/template.comp`). It then creates the real pipeline from that with
  `VK_KHR_pipeline_binary`. The pipeline layout is vkd3d's plus one descriptor set of the layer's.
* At each dispatch of such a pipeline it copies the kernel's surfaces from vkd3d's descriptor heap into its set and
  binds it.
* It answers the shim's self-test (`anv_canary`) only after its own check on the device has passed. With a driver
  version it does not know, the shim declines and XeSS uses DP4a.

The serialized form differs between Mesa versions. `src/layouts.h` has one table per version: 26.1, 26.3 and
27.0-devel. The values were measured with `tests/layout_probe.py` on binaries exported from the variant shaders in
`tests/variants`, not taken from Mesa's sources.

## Build

    VULKAN_HEADERS=<Vulkan-Headers checkout> ./build.sh [out dir]   # gcc, glslangValidator, python3; default out/
    ./tests/build.sh                                                 # unit tests

The headers must define `VK_KHR_pipeline_binary`; the layer is built with Vulkan-Headers 1.4.350.

## Use

    VK_ADD_LAYER_PATH=<out dir> VK_LOADER_LAYERS_ENABLE=VK_LAYER_XESS_xmx \
    XMX_LAYER_HELPER=<package>/tools/cm-compile.sh XMX_IGC_DIR=<package>/igc %command%

The Vulkan driver must be an unpatched ANV. If the session points `VK_DRIVER_FILES` at the package's patched driver,
point it back at the distribution's `intel_icd.*.json`.

| Variable | Effect |
|---|---|
| `XMX_LAYER_LOG` | `1`: log to stderr; a path: append to that file |
| `XMX_LAYER_HELPER` | the compile script (else `ANV_CM_HELPER`, else `tools/cm-compile.sh` next to `ANV_CM_KERNEL_DIR`) |
| `XMX_LAYER_PROF=1` | GPU time of every replaced dispatch, a per-kernel table in the log every 5 s |
| `XMX_LAYER_PROF=2` | one time stamp pair per run of back-to-back replaced dispatches, reported as one row `runs` (XeSS' GPU time including the gaps between its dispatches) |
| `XMX_LAYER_PROF_SEC` | report period in seconds |
| `XMX_LAYER_DISABLE=1` | turn the layer off |
